# Spatial and portable planning decision

For #30, permit planner-authored meeting, walk and activity stops with visible “Added by the planner” provenance. This keeps a real meetup or stroll in the shared plan without inventing a source event. A provider-only model would require paid configuration and could not represent an informal activity. Event stops continue to re-read all display facts from the database; caller text cannot override them.

Planner text is bounded single-line plain text, rejecting markup, control/bidirectional characters and URL forms. Titles, place names and addresses have separate limits. Times require explicit timezone offsets; end must follow start. Coordinates require a complete finite, bounded pair. User stops have no ticket URL or event identity. Maps links use encoded destination/origin data and fixed Google Maps hosts. Coordinates are planner statements, not verified venue facts. Shared origin and stop details are deliberately public: the UI must disclose this before publication. Raw prompts remain private; owned expiry, revocation, JWT-only publication and cache controls remain intact.

Origin is optional place text and/or coordinates. Only coordinates influence ranking, with a bounded travel penalty over existing scores; text is passed to Maps for routing without silently geocoding it. Driving remains the default; walking, cycling and transit are explicit modes. No routing API is used. Distance-based buffers include an indirect-path allowance and per-mode overhead; they are approximate planning estimates, not traffic, timetable or kitchen-hours claims. Missing trusted coordinates retain a 30-minute fallback. Estimated event start times do not generate precise leave-by times.

Spatial intent resolution initially uses explicit approximate search circles for SF areas and landmarks, not claimed administrative boundaries. Both anchor and support queries apply PostGIS radius constraints and the 0.7 navigation confidence threshold. Existing city-wide behavior remains when no spatial area resolves. The response and UI expose the chosen label, center and radius; unsupported places retain existing handling rather than fabricate coordinates. No paid provider, ingestion, existing-corpus migration or deployment is authorized by this change.
