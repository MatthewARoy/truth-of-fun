## Adapter and coverage-check design

A manifest should name the official source URL/domain, supported format (JSON-LD Event, iCalendar or a reviewed site-specific extraction recipe), season/date bounds and known venue mapping. The shared adapter retains only actually published occurrence dates, event-specific URLs, cancellation/estimated-time status and explicit free/admission qualifiers. Apply request/page/result budgets, existing retry/health telemetry and stable provider occurrence identities. Generic season text does not become a repeating weekly series without dated source evidence.

The independent coverage report accepts a bounded set of official occurrence expectations with evidence URLs, expected dates and freshness, and compares those exact title/date/venue identities against the database. States: covered, missing while corpus fresh, corpus stale, expectation stale, and off-season/outside ingest horizon. Generic umbrella rows and dev seeds cannot satisfy a dated occurrence. Missing credentials or an inactive season must remain distinguishable from parse failure. Run on demand first; scheduling or live scraping is not activated here.

The on-demand check is now implemented in `scripts/audit_civic_coverage.py` with a reviewed occurrence manifest in `docs/civic-expectations-2026-09-29.json`. The manifest records actual official event-specific dates for African Arts Festival (October 3), Quinteto Latino (October 8), Halloween Hoopla (October 31), the announced 2027 Nihonmachi date outside the near-term horizon, and a Golden Gate Park Band season reference with no invented future occurrence. The three Yerba Buena event pages and Nihonmachi page were rechecked September 29, and the band season page was separately rechecked later that evening; individual links and check times are in the manifest. The manifest is a bounded canary, not an exhaustive calendar.

Run `PYTHONPATH=. DATABASE_URL=... .venv/bin/python scripts/audit_civic_coverage.py --manifest docs/civic-expectations-2026-09-29.json`. Reads enforce a PostgreSQL READ ONLY transaction and a statement timeout, select only public catalog/source-health fields, cap the horizon at 365 days and refuse snapshots exceeding 10,000 rows. No provider calls, scraping or scheduling occurs. Exit codes: 0 covered/inactive dates; 1 a missing dated expectation with fresh complete evidence from every named coverage path; 2 input/database-read failure; 3 stale or unverified evidence. A source must have a healthy, nonpartial success in the last 24 hours and after the official expectation check, and its reviewed configured crawl window must reach the expected date. The manifest records current worker defaults: Funcheap 10 days, SFStation and DoTheBay 7, Eventbrite 14 (inclusive from crawl start). The reader reserves one calendar day because health timestamps record completion and bounded default crawls can cross SF midnight. This can defer a canary at the far boundary; it prevents claiming an extra uncrawled day. Sources outside that window are not evidence of an omission; if none reach the date, the result is outside_source_horizon. Missing horizon configuration is coverage_horizon_unverified. Actual run-boundary telemetry is not stored today: these gates assume the standard worker/default source configuration, so update the manifest and verify per-run scope before using overridden crawls or connecting exit 1 to alerting. Official expectations expire after 14 days, requiring a re-check before later programs can become actionable. Existing matches may be reported covered with stale-source diagnostics, which proves stored representation rather than fresh attendance eligibility.

Fixtures verify separate venue/date identities, SF calendar dates across UTC midnight, umbrella/seed/cancelled exclusions, partial/error/stale/future health evidence, expectation expiry, off-season/past/outside-horizon states and database-write rejection. The adapter recommendation remains research; before implementing/activating an official feed, validate current page format, fetch permissions and fresh deployed counts. This completes the audit, design decision and executable coverage check in #24; it does not establish complete civic coverage or activate new ingestion.

Review repairs use the registered SourceId vocabulary to exclude seed/unknown providers, while allowing legitimate titles containing words such as demo or seed. Database connection values are accepted only through DATABASE_URL, avoiding credential-bearing CLI arguments. Validation identifies manifest fields without echoing input values. Tests load the shipped manifest, compare declared horizons with current source defaults, and exercise CLI exit codes, dialect/size/row guards and inclusive date/freshness boundaries.

Operational review: exit 3 is a request to refresh or complete evidence, not an event-omission alert. The undated band season reference intentionally makes the current shipped manifest return 3; dated expectations expire after 14 days. Recheck official dated pages at least every two weeks while using the canary, retain per-occurrence statuses, and route only confirmed exit-1 omissions after checking title/venue aliases and crawl scope. Address-only or alternate venue spellings can require manifest alias updates. The 180-day reader also refuses growing catalogs above 10,000 rows rather than claiming coverage from a truncated snapshot; narrow the on-demand horizon when appropriate.
